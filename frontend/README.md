# 企智搭·代码平台 —— 前端控制台

React + TypeScript + Vite 的单页应用，后端是仓库里的 `backend/`（FastAPI）。

## 起服务

```bash
cd frontend
npm install
npm run dev
```

打开 <http://localhost:6001>。

**端口 6001**，写死在 `vite.config.ts` 里（`strictPort: true`，端口被占就直接报错，
不静默换端口）。

## 连后端

前端只用相对路径 `/api`，由 **Vite dev server 转发**到后端：

```text
浏览器 → /api/v1/xxx → Vite proxy → http://127.0.0.1:<后端端口>/api/v1/xxx → FastAPI
```

走代理而不是直连的原因：省掉 CORS、SSE 不用特殊处理、生产同域部署时前端代码
一行都不用改。

**后端端口默认取后端 `.env` 里的 `PORT`**（当前是 8000），所以克隆下来两端
都能用默认配置跑起来。

用 `--port` 临时改了后端端口的，前端要跟着设环境变量：

```bash
VITE_API_PROXY_TARGET=http://127.0.0.1:8080 npm run dev
```

> ⚠️ **后端必须从 `backend/` 目录启动**。`.env` 在那儿，`Settings` 是按当前工作
> 目录找它的 —— 在仓库根目录启动会读不到配置（API Key 空、数据库连到另一个空库）。
>
> ```bash
> cd backend && ../.venv/bin/uvicorn app.main:app --reload
> ```

## 主题：跟随系统 / 浅色 / 深色

三档，不只是开关 —— 只做「浅/深」两档的话，用户手动设了深色之后，系统切到浅色
他不会跟着变，而「跟随系统」那档能解决。

深浅的切换靠给 `<html>` 挂 `.dark` 类（Tailwind v4 的 `dark:` 变体已从
`prefers-color-scheme` 改成 class 策略）。

**组件里不许写具体色值** —— 一律用语义类（`bg-base` / `text-ink` /
`border-subtle`），具体值只在 `theme/tokens.css` 里改。语义 token 而不是色板：
`slate-500` 只说了颜色，深色下得整体重映射一遍；语义 token 直接表达「这是次要
文字」，深浅两套各给一个值，组件不用动。

## 品牌色：朱砂橙

主色是**朱砂橙**（东方红）—— 浅色 `oklch(0.58 0.16 38)` / 深色 `oklch(0.76 0.15 45)`。
底色是暖纸感（hue 78），两者同属暖色系，放在一起是「宣纸 + 朱印」的东方气质。

**品牌色只出现在该出现的地方** —— 整体界面保持中性，内容才是主角：

| 位置 | 表现 |
| --- | --- |
| 侧栏 logo | 品牌渐变方块 |
| 发送按钮 | 品牌色实心圆 |
| 当前会话 | 左侧品牌色竖条 |
| 链接 / 强调 | 品牌色 |
| 聚焦环 | 品牌色的淡环（`--ring`） |
| 输入框聚焦 | 边框变品牌色 + 一圈光环 |
| 空状态背景 | 暖色中心光晕 |

**改品牌色只改 `src/theme/tokens.css` 一处** —— 组件全部走 `accent` 系列语义类，
`src/` 里没有一处 Tailwind 默认色板或十六进制色值。

## 输入框的三项能力

输入框（`features/agent/Composer.tsx`）里能用的三样东西：

| 能力 | 怎么用 | 落到哪 |
| --- | --- | --- |
| **添加文件或图片** | `+` 菜单 → 添加文件或图片 | 上传到会话工作区的 `uploads/`；图片**内联**进这一轮的消息，模型当场看得见 |
| **斜杠命令** | 敲 `/`，或 `+` 菜单 → 斜杠命令 | `prompt` 类填一段提示词（改完再发）；`action` 类触发本地动作（换模型、开新会话…） |
| **@ 提及** | 敲 `@`，或 `+` 菜单 → 提及文件或目录 | 路径写进正文（`@/uploads/a.png`）；**被提及的图片自动带成附件**，模型这一轮看得见 |

**命令清单在后端**（`GET /api/v1/agent/commands`）—— 前端只渲染，不硬编码；
后端加了命令前端自动就有。

**触发符的识别规则**在 `Composer.tsx` 的 `detectTrigger`：触发符前面必须是空白
或行首，所以 `/uploads/x.png` 这种路径不会被当成斜杠命令，`@` 后面可以直接跟路径。

`@` 面板列的是**工作区的文件与目录**（`GET /api/v1/files/tree`）—— agent 建的
文件也能提到。每次打开面板会重新读一次，因为 agent 可能刚建了新东西。

## 对话正文：全量 Markdown

**助手和用户的正文都按 Markdown 渲染**（`features/markdown/Markdown.tsx`）。
模型输出的 `**粗体**` 得是粗体，不是把星号露给用户看。

支持的语法：

| 语法 | 说明 |
| --- | --- |
| 标题 | `#` ~ `######` |
| 强调 | `**粗**` `*斜*` `~~删除线~~` |
| 列表 | 无序、有序、**嵌套**、任务列表 `- [x]` |
| 表格 | GFM 表格，带列对齐（`\| --- \| :---: \|`） |
| 代码 | 行内代码、围栏代码块（语言标签 + **复制按钮** + 语法高亮） |
| 其他 | 引用块、分隔线、链接、图片、自动链接 |

实现是 `react-markdown` + `remark-gfm` + `rehype-highlight`：

- **原始 HTML 不渲染** —— 不挂 `rehype-raw`。助手消息来自模型，而模型会被诱导
  输出 HTML；不渲染就只是显示成一段文字，渲染了就是 XSS。
- **语法高亮认别名** —— `tsx` 当 typescript、`vue` 当 xml；认不出来的语言就
  不高亮（`rehype-highlight` 对未知语言只记一条 message，不抛错）。
- **样式全在 `.md` 作用域里**（`markdown.css`），不污染页面其余部分；颜色只用
  语义 token，代码高亮那组是 `--code-*`（深浅各一份）。

`CodeBlock` 里有个细节：**渲染用的是高亮后的节点树，复制用的是另抽的纯文本**。
自己抽文本会把颜色丢了。

## 侧栏

侧栏从上到下：**产品头**、**动作**（新建 / 搜索）、**模块入口**、**会话列表**
（已置顶 + 对话和任务）。

| 能力 | 说明 |
| --- | --- |
| 新建 | 立刻建一个会话进列表（不是等用户发了第一条消息才进），跳到 `/chat/<id>` |
| 搜索 | 按标题过滤会话列表 |
| 删除 | 从侧栏列表里删掉这条会话记录（**后端的对话记录还在** —— 见下面的已知缺口） |
| 置顶 | 把会话挪到「已置顶」组 |

**发消息的一瞬间就建会话、跳路由**，不等流跑完 —— 流式期间侧栏看不到这个
会话，用户这时刷新页面，draft id 会重新随机生成，后端的 checkpoint 就成了
孤儿，再也进不来了。

**改过的标题不会被消息内容冲掉** —— 只有默认的「新会话」才让消息标题顶掉它。

**标题里不带 Markdown 记号** —— 正文渲染成 Markdown 了，标题却是裸的
`# 标题` 看着像坏了一样。`titleFromMessage` 会把 `#`、`**`、`` ` ``、引用、
列表记号去掉。

### 上下文占用 与 会话状态面板

**输入框底栏里有个「上下文占用」指示器**，就在**模型选择的左边** —— 一行
「上下文 15.6%」加一根小进度条。点一下**弹开明细**（各占多少：对话消息 /
系统提示词 / 工具定义 / MCP 工具 / 技能 / 记忆文件），再点收起。

它**在输入框这一行里，不另起一根条** —— 上下文是这一轮对话的事，就该待在输入
框旁边，而不是浮在上方抢地方。

**新会话是 0%。** 系统提示词和工具定义是每次请求都带上的，可请求还没发出去，
占用的就是 0 —— 弹层里会写「还没开始对话」。

**压缩缓冲不算占用。** 它是预留出来放摘要的那段（窗口用到 85% 就触发压缩，
那 15% 得一直空着），单列一行标着「（预留）」，**不计入已用**，但要从剩余空间
里扣掉。所以「已用 + 压缩缓冲 + 剩余空间 = 整个窗口」。

浮层里还有一条「在右侧打开完整面板」——**右侧拉开一整列**（参考 Claude 桌面端：
面板占右边，中间是对话区）。面板里每一段是一张独立的卡片：

- **环境** —— 工作区路径、模型、供应商、信任模式（**供应商报的是类型**
  `deepseek` / `openai`，不是用户给配置起的名字）；
- **上下文** —— 占了窗口的百分之多少，分别被对话消息 / 系统提示词 / 工具定义 /
  MCP 工具 / 技能 / 记忆文件占掉多少；记忆文件和 MCP 工具可以展开看明细；
- **连接** —— 接进来的模型供应商与 MCP 服务器；
- **产出** —— 工作区里的文件与上传件；
- **改动** —— 这个会话一共改了多少行（`+N −M`）；
- **后台任务** —— 现在在跑的工具调用（沙箱里跑命令那些），以及跑完了多少个。

指示器浮层和右栏的「上下文」卡片**共用同一份明细渲染**
（`features/sessions/ContextBreakdown.tsx`），两处不会算出不一样的数。

输入框里同时只开一个浮层 —— 开模型菜单会把上下文浮层收掉，反过来也一样。

**一轮对话跑完会立刻重读一次** —— 光靠 30 秒轮询的话，刚聊完的数字还停在
上一轮，看着像没变。右栏面板也是开着就每 30 秒刷一次。

**上下文占用是估算**（4 字符约 1 token），面板上写明了 —— 别拿它当精确的
token 数看。后端在 `app/agents/status.py`；在跑的任务在 `app/agents/tasks.py`
（**进程内存里**，重启就清空 —— 它是实时视图，不是审计记录）。

## 页面

| 路由 | 内容 |
| --- | --- |
| `/chat` `/chat/:threadId` | **编码助手** —— 唯一支持多轮对话的页面 |
| `/files` | 工作区文件（上传件与产物）。**看的是当前会话的工作区**（`?thread=`，侧栏点进来会带上）；能上传、预览、改内容、改名、删除，也能「打包下载」整个工作区 |
| `/environments` | **工作目录** —— 白名单下的仓库与目录、平台派生的 worktree；能建 worktree、删 worktree |
| `/providers` | 模型接入配置 —— 新增 / 编辑 / 删除 / 看详情 / 测连通性 |
| `/capabilities` | 能力清单 —— 四个标签页：清单（只读）、工具、技能、MCP，各带增删改查 |
| `/status` | 前后端联通检查（真实调接口并显示响应体） |

### 三个管理页的增删改查

| | 新增 | 查看 | 更改 | 删除 |
| --- | --- | --- | --- | --- |
| **模型接入** | 新增配置 | 详情弹窗 | 编辑表单 | 删除（要确认） |
| **能力清单 · 工具** | 新增工具 | 详情弹窗 | 编辑表单 | 删除（会清掉技能里的引用） |
| **能力清单 · 技能** | 新增技能 | 详情弹窗 | 编辑表单 | 删除 |
| **能力清单 · MCP** | 新增服务器 | 详情弹窗 + 探测工具 | 编辑表单 | 删除 |
| **文件** | 上传 | 预览（文本看内容、图片看图） | 改内容、改名 | 删除（要确认） |

弹窗与表单控件在 `components/ui/`（`Modal` / `Button` / `Fields`）—— 一套框，三个
页面共用，别再各写各的。

**几个要注意的地方**：

- **API Key 只有写没有读** —— 后端只回脱敏串（`sk-***1b5d`）。编辑时留空就是
  "不修改"，填了才换。
- **builtin 工具的来源是下拉** —— 只能从内置白名单里选（`GET /tools/builtins`），
  平台不允许自建任意入口；mcp 类型的来源是已配置的 MCP 服务器名。
- **入参 schema 只有 http 类型才要填** —— builtin / mcp 传空字典是正常的。
- **改文件内容只处理文本** —— 二进制走上传。
- 删除一律要确认（`window.confirm`）；删工具会连带清掉技能里对它的引用。

**工具表里的「权限 / 风险」那一列**显示的是档位 + 要不要人批：

| 显示 | 含义 |
| --- | --- |
| `低 · 自动放行` | 只读、写入 —— 改错了能改回来 |
| `中 · 要人批` | 执行命令、联网 —— 会在进程外产生副作用 |
| `高 · 要人批` | 破坏性 —— 不可逆，永远要人批 |

档位与显示规则在 `features/capabilities/risk.ts`（纯函数，可单测）；**判定在后端**
（`app/capabilities/registration/policy.py`），前端不自己再判一遍。

新增工具时表单里的两个选择项：

- **风险等级** —— 决定档位（中档要人批，高档永远要人批）；
- **权限要求** —— 档位之上的额外要求：「一定要人批」（运营显式要求）与
  「管理员放行」。默认的「按风险档位判定」就是跟着档位走。

## 工作目录（环境）

会话默认在平台自带的空白工作区里干活。绑一个**真实的代码仓库**当工作目录，
agent 就在那个目录里读写文件、跑命令。

### 初始状态的那一条

新会话（**初始状态**）的对话框**下方**有一行：

```text
[📁 会话工作区]  [⑂ Worktree]
```

点开是环境清单，分三段：

- **仓库** —— **选中就自动开一个新分支 + 一份独立检出**，不用另外配置；
- **本地目录** —— 直接选一个本地目录当会话工作区；
- **Worktree** —— 已经开好的检出，直接绑上。

顶部有个搜索框（白名单下的目录可能有几十个），底部是「新建工作区」：
起个名字 + **选一个本机目录**。

选目录不是固定的下拉框 —— 是一个能往下钻的浏览器：点子目录进去、「上一级」退回、
或者把路径粘进去（在访达里按 `⌘⌥C` 复制路径，回车跳过去）。**只能选白名单内的
目录** —— 目录浏览也是读宿主机的文件系统。

**没有「新建 worktree」那一档** —— 选中仓库就会自动分配，独立检出不是一个
需要单独配置的动作。

**只在初始状态出现** —— 聊起来之后它就不占地方了（要换目录去「工作目录」页）。

### 协作状态

右侧状态面板有一段「协作」：当前绑在哪个目录、哪个分支、仓库里还有哪些
worktree。

派出去的子 agent（`delegate_worker`）会留下分支 —— **分支不会自动合回主线**，
那一段就是给人看"还剩哪些分支没收"的。要合由人来合（页面上的合并入口，
或者自己在仓库里合）。

### 白名单

平台没有鉴权，后端的白名单（`REPO_ROOTS`）是唯一的闸门 —— **没配就一个目录都
不能绑**，前端会明确显示这一点，而不是给一个空列表让人猜。

## 对话区的操作

助手消息右下角有**操作条**（鼠标移上去才出现）：

| 操作 | 做什么 | 怎么实现的 |
| --- | --- | --- |
| 复制 | 复制这条回复的纯文本 | 前端，剪贴板 |
| 重新生成 | 把上一轮删掉重跑一遍 | `POST /agent/{thread_id}/regenerate`（SSE） |
| 分支 | 从这条消息切出新会话 | `POST /agent/{thread_id}/fork` |

**重新生成**与**分支**都作用在后端的 checkpoint 上（见 `app/agents/runner.py`
的 `regenerate()` / `fork()`），只用 LangGraph 的公开接口
（`update_state` + `RemoveMessage`），不碰 checkpoint 表里的 blob。

- **重新生成**：从最后一条用户消息起（含它）往后全删，再用那条用户消息重跑。
  前端也得跟着删 —— **但要保留那条用户消息**（后端是拿它重跑的，它还在历史里）。
- **分支**：新会话用 `update_state` 播种（写入切到分支点为止的消息），**不跑模型**；
  工作区文件也复制过去 —— 只带对话不带文件的话，新会话是空的。
  分支点是靠**消息 id** 定位的（历史接口现在会带 `message.id`）。

## ⌘K 命令面板

`⌘K` / `Ctrl+K` 打开。列的是"页面多起来之后藏在侧栏里太深"的动作：
新建会话、切到文件/能力/模型页、打开右侧状态面板、切主题。

- 焦点在输入框里时**不弹** —— 那是用户要输内容的地方。
- 过滤匹配**标题、副标题、关键词**三处 —— 用户常常记得"那个管文件的命令"
  而记不住它叫什么。
- ↑↓ 选、Enter 执行、Esc 关闭（跟斜杠命令面板一套）。

过滤规则在 `features/commands/filter.ts`（纯函数，可单测）。

## 聊天页的事件流

后端 `/agent/stream` 推的**一帧一种事件**（`type` 字段决定）：

| 事件 | 前端动作 |
| --- | --- |
| `text` | 追加到最后一条助手消息（打字机） |
| `tool_call` | 加一个工具折叠块（进行中） |
| `tool_result` | 按 tool_call_id 找到那个块，补上结果 |
| `pending_approval` | 弹审批卡片 |
| `error` | 这一轮炸了 —— 显示原因（**不能少**，少了一帧界面就停在「思考中…」） |
| `done` | 收尾 |

多轮靠 `thread_id` 串 —— 后端用 checkpoint 存历史，前端一直带着同一个 id。
刷新页面后从 `GET /agent/{thread_id}/history` 拉回来。

**批准 / 拒绝之后要重读历史**：图恢复后 agent 会接着往下跑，**可能又撞上新的
审批**（批准一张卡不等于这一轮结束）。只把当前这张卡关掉的话，新的待批就丢了
—— 页面看着像卡住了。所以批准/拒绝之后重新拉一次历史与待批清单
（`loadHistory`），让新的审批卡片出来。

**会话列表在 localStorage**（标题、置顶）—— 后端没有会话表，这是已知缺口。
消息在 checkpoint 里，清了浏览器数据只是列表没了，消息还在。

**删会话只删侧栏的记录** —— 后端的 checkpoint 与工作区文件都还在。
`/clear` 斜杠命令才是真删（`DELETE /agent/{thread_id}`，删 checkpoint，
工作区文件留着）。

## 权限模式

输入框底部有一个**权限模式**选择器（盾牌图标），决定这一轮要不要人批 —— 语义
对齐 Claude Code 的权限模式：

| 模式 | 行为 |
| --- | --- |
| 自动（推荐） | 按风险档位：只读与写入直接放行，执行命令、联网、破坏性操作要人批 |
| 手动 | 任何会改东西的操作都要人批，只读不问 |
| 接受编辑 | 文件编辑与命令都自动放行，只有破坏性操作要人批 |
| 只读 | 写文件与执行命令的工具不提供给模型，只做阅读与规划 |
| 绕过权限 | 所有操作直接执行，不会有人工审批（切换时要二次确认） |

模式是**会话级**的，存在后端（`<workspace_root>/.qzd/permissions/`）——
别的进程也要看得见（审批恢复可能落在另一个进程上）。切换后**下一轮**生效；
当前挂起的那次调用还是要点「批准」。

「绕过权限」会连破坏性操作一起放行，切换时弹一次确认。

## 工具调用卡片

每次工具调用渲染成一张卡片（`features/agent/ToolCallBlock.tsx`）：

**折叠时一行** —— 图标 + 人话标签 + 目标 + 改动量 + 耗时 + 状态点。
标签是中文的（`read_file` → 「读取文件」），目标取参数里最能说明问题的那一项
（路径 → 模式 → 命令 → 代码首行）。**这一行是给人扫的**，不是给人读的。

**展开才给细节** —— 参数逐行列出（不是一坨 JSON），结果是一个带边框的代码面板。

失败时图标块、状态点、结果面板一起转成危险色。

摘要规则都在 `features/agent/toolSummary.ts`（纯函数，`npm test` 能跑）：

| 函数 | 做什么 |
| --- | --- |
| `toolLabel(name)` | 工具名 → 人话；不认识就原样返回 |
| `toolTarget(args)` | 参数里最能说明"做了什么"的那一项 |
| `toolArgRows(args)` | 参数 → 逐行展示（对象/数组标成结构化） |
| `isFailedResult(text, tool?)` | 认得出失败的结果 |

**读文件要带行范围**：长文件常常是分段读的（`offset`/`limit`），只显示路径的话，
卡片上就是一排一模一样的「读取文件 /backend/README.md」—— 看着像在反复读同一个
文件。`toolTarget` 会把范围带出来：`/backend/README.md（101-320 行）`。

**历史消息里的失败怎么认的**：deepAgents 的文件工具失败时**不抛异常**，而是把
`Error: ...` 写进结果里；命令类工具（`execute`）更是只把 stderr 写进去，连
退出码都不给。历史接口没有 ok 字段，所以前端认这两类特征（`isFailedResult`）——
不认的话，失败的卡片会显示成绿勾。

**还没执行的调用不能显示成绿勾**：历史里的工具调用先当"进行中"，结果到了才改成
成功/失败 —— 在等人工审批的调用就是没有结果。

## 约定

**类型要跟后端 schema 对齐**。前端没有代码生成，改了后端 schema 要手工同步
`src/types/api.ts`。

**页面不直接调 `api.get`**，走 `src/api/resources.ts` —— 路径与参数收在一处。

**鉴权留了口子**：`client.ts` 的 `setHeaderProvider` 现在返回空对象。平台目前
没有鉴权（后端所有接口都是裸的），将来加登录/令牌只改这一处。

**`/api/v1/health` 返回的是裸对象**，没有 `ResponseModel` 那层 —— 所以
它走 `api.getRaw`，不是 `api.get`。

## 命令

```bash
npm run dev      # 开发服务器（6001）
npm run build    # 类型检查 + 生产构建
npm run preview  # 预览生产构建
npm run lint     # oxlint
npm test         # 纯函数的单测（触发符、会话标题）
```

`npm test` 跑的是 `scripts/*.mjs` —— Node 24 能直接跑 `.ts`（类型擦除），
所以纯函数不用先构建。**只有纯函数能这么测**：`.tsx` 里带 JSX，Node 跑不了
（`titleFromMessage` 之所以单独放在 `features/sessions/title.ts` 就是这个原因）。
